# ADR-001: Technology Stack Selection

## Status
Accepted

## Context
We needed to select a technology stack for the Demo-Nagma Tattoo CRM application that would:
- Support rapid development and iteration
- Provide excellent performance for real-time booking applications
- Offer strong TypeScript support
- Have a mature ecosystem for enterprise applications
- Be maintainable by our development team

## Decision
We selected the following stack:
- **Backend**: Node.js with Express.js framework
- **ORM**: Prisma 6
- **Database**: PostgreSQL 17
- **Language**: TypeScript 5.x

## Consequences

### Positive
- **Developer Experience**: Excellent TypeScript support throughout the stack
- **Productivity**: Prisma's type-safe database access reduces boilerplate and catches errors at compile time
- **Performance**: Non-blocking I/O of Node.js handles concurrent connections well for booking systems
- **Ecosystem**: Large npm ecosystem for extending functionality
- **Familiarity**: Team already experienced with JavaScript/TypeScript ecosystem
- **Scalability**: Vertical scaling works well; horizontal scaling achievable with load balancers

### Negative
- **Single-threaded Nature**: Node.js is single-threaded per process, requiring clustering for CPU-intensive tasks
- **Relational Learning Curve**: Team needed to learn Prisma specifics despite SQL experience
- **Enterprise Perception**: Some enterprises perceive Node.js as less "enterprise" than Java/.NET (addressed through proven reliability)

## Alternatives Considered

### Django (Python)
- **Pros**: Excellent ORM, built-in admin, strong security features
- **Cons**: 
  - Python's GIL limits true parallelism
  - Less ideal for real-time features
  - ORM less type-safe than Prisma with TypeScript
  - Team would need to learn Python/Django stack

### Ruby on Rails
- **Pros**: Convention over configuration, excellent developer happiness
- **Cons**:
  - Performance characteristics not ideal for high-concurrency booking systems
  - Declining job market making hiring harder
  - Asset pipeline complexity
  - Team lack of Ruby experience

### NestJS (Node.js)
- **Pros**: 
  - Built on Express, provides more structure out-of-the-box
  - Excellent TypeScript support
  - Built-in dependency injection
- **Cons**:
  - Additional learning curve for team
  - More abstraction than needed for our use case
  - Larger bundle size for simple applications
  - We preferred Express's minimalism and direct control

### Microsoft SQL Server / Entity Framework
- **Pros**: Excellent enterprise tooling, strong performance
- **Cons**:
  - Licensing costs for enterprise features
  - Less ideal for cross-platform deployment
  - Heavier weight than PostgreSQL
  - Team expertise primarily in open-source stack

## Implications
- **Development**: Faster feature delivery due to TypeScript safety and Prisma productivity
- **Operations**: Simplified deployment with Docker; mature monitoring tools available
- **Growth Path**: Clear path to micro-services if needed via well-defined API boundaries
- **Risk Mitigation**: Long-term LTS support for Node.js and PostgreSQL provides stability
